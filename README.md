# Лабораторная работа №1: BST и множество на C++20

Самостоятельная header-only библиотека `SearchTree<T, Compare>` и `OrderedSet<T, Compare>`. Множество хранит элементы в собственном бинарном дереве поиска. Дерево не балансируется, а уникальность ключей определяется компаратором. Для знакомства с библиотекой есть консольная демонстрация.

[Проектный дизайн и схемы алгоритмов](design.md) описывают архитектуру, обходы, удаление, работу с поддеревьями, восстановление из строки и очистку дерева. Выбранные пункты задания дают **28 баллов**.

## Сборка и запуск

Нужны компилятор C++20 и CMake 3.24 или новее.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/tree_lab_demo
```

Для тестов CMake сначала ищет установленный GoogleTest. Если пакет не найден, скачивает GoogleTest 1.17.0. Для сборки без сети укажите `-DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=/путь/к/googletest` для локальных исходников или `-DGTest_DIR=/путь/к/lib/cmake/GTest` для установленного пакета.

## Подключение библиотеки

Добавьте путь к каталогу `include/` через `-Iinclude` и подключите нужные заголовки. Следующий пример находит сумму ключей из интервала, восстанавливает дерево из строки и сравнивает два множества.

```cpp
#include <tree_lab/ordered_set.hpp>
#include <tree_lab/search_tree.hpp>
#include <iostream>

int main() {
    const SearchTree<int> tree{12, 5, 18, 2, 9, 15};
    const auto selected = tree.where([](int value) {
        return 5 <= value && value <= 15;
    });
    const int sum = selected.reduce([](int value, int total) {
        return total + value;
    }, 0);
    std::cout << "Сумма ключей от 5 до 15: " << sum << '\n'; // 41

    const auto saved = tree.to_string();
    const auto restored = SearchTree<int>::from_string(saved);
    std::cout << "Поддерево с корнем 5 найдено: " << std::boolalpha
              << restored.contains_subtree(tree.subtree(5)) << '\n'; // true

    const OrderedSet<int> planned{101, 102, 104};
    const OrderedSet<int> completed{102, 103};
    std::cout << "Остались задачи:";
    for (int id : planned - completed) {
        std::cout << ' ' << id; // 101 104
    }
    std::cout << '\n';
}
```

В проекте на CMake добавьте каталог лабораторной и привяжите цель `tree_lab` к своему приложению:

```cmake
add_subdirectory(path/to/tree_lab)
target_link_libraries(my_application PRIVATE tree_lab)
```

При подключении через `add_subdirectory` примеры, тесты и бенчмарки выключены по умолчанию. При самостоятельной сборке ими управляют `TREE_LAB_BUILD_EXAMPLES`, `TREE_LAB_BUILD_TESTS`, `TREE_LAB_BUILD_BENCHMARKS`. Чтобы проверить только подключение библиотеки, все три опции можно установить в `OFF`. Ни GoogleTest, ни Python для этого не нужны.

## API и семантика

Оба контейнера предоставляют `insert`, `erase`, `find`, `contains`, `size`, `empty`, `clear`, `key_comp`, `swap`, `begin`, `end`, `values`, `for_each`, `map`, `where`, `reduce`, `to_string`, статический `from_string` и потоковые операторы. При копировании создаются отдельные узлы. Перемещение между разными объектами передаёт владение и оставляет источник пустым. Самоприсваивание допустимо.

- `insert` возвращает `false` для эквивалентного ключа; существующее значение не заменяется. Эквивалентность: `!compare(a,b) && !compare(b,a)`.
- `find` возвращает `std::optional<std::reference_wrapper<const T>>`: пустой результат при отсутствии ключа, иначе `found->get()` даёт константную ссылку. Она не владеет узлом и не продлевает его жизнь. Вставка и удаление других элементов её не инвалидируют. После удаления найденного элемента, очистки, замены или уничтожения владеющего контейнера пользоваться ссылкой нельзя. Сам `optional` при этом автоматически не обнуляется.
- `erase` возвращает `false` для отсутствующего ключа. При двух потомках узел заменяется узлом-преемником, без присваивания `T`.
- `map(f)` принимает `f(const T&)`, вставляет преобразованные значения в новый контейнер того же типа `T, Compare` и исключает дубликаты. `where(predicate)` вставляет в новый контейнер значения, прошедшие условие. Оба алгоритма читают источник в КЛП. При тождественном преобразовании или отборе всех значений сохраняется форма дерева.
- `reduce(f, initial)` вызывает `f(element, accumulator)` в порядке ЛКП. Аккумулятор может иметь другой тип и поддерживать перемещение без копирования. Для пустого контейнера результатом служит начальное значение.
- `for_each(f, order)` передаёт `const T&`. Порядок по умолчанию — ЛКП. Во время обхода нельзя менять тот же контейнер из callback через внешний неконстантный доступ.

| Обход | `TraversalOrder` |
|---|---|
| КЛП | `root_left_right` |
| КПЛ | `root_right_left` |
| ЛКП | `left_root_right` |
| ЛПК | `left_right_root` |
| ПКЛ | `right_root_left` |
| ПЛК | `right_left_root` |
| BFS (по уровням слева направо) | `breadth_first` |

У `SearchTree` и `OrderedSet` обычные `begin()` и `end()` дают обход ЛКП в порядке компаратора. В `values(order)` можно выбрать любой из семи порядков. Множество делегирует обход своему дереву. `for_each` использует те же итераторы и вызывает переданную функцию для каждого значения.

```cpp
const SearchTree<int> tree{12, 5, 18, 2, 9, 15};
const OrderedSet<int> ids{120, 105, 180, 109, 115, 105};

for (const auto& value : tree) {
    std::cout << value << ' '; // ЛКП: 2 5 9 12 15 18
}
std::cout << '\n';

for (const auto& id : ids.values(TraversalOrder::breadth_first)) {
    std::cout << id << ' '; // BFS: 120 105 180 109 115
}
std::cout << '\n';
```

Итератор возвращает `const T&` и вычисляет следующую позицию при продвижении. Диапазон `values(order)` ссылается на контейнер, который должен существовать до конца обхода. Передача неизвестного порядка приводит к `std::invalid_argument`. После структурного изменения контейнера получите итератор заново. Если прежняя позиция не нужна, используйте `++it`, чтобы избежать копирования состояния обхода. [Схема итератора в дизайне](design.md#а7-итераторы-дерева-и-множества)

Только BST: `subtree(root)` копирует значения и структуру поддерева, бросает `std::out_of_range` при отсутствии корня. `contains_subtree(other)` ищет кандидата на корень по компаратору и проверяет точную структуру и `operator==` значений. Для этой операции равные значения должны иметь эквивалентные ключи. Обратное необязательно: у студентов одинаковый ID может соответствовать разным полям записи. Пустое дерево входит в любое дерево.

Для чтения структуры есть `for_each_node(f)`: итеративный обход КЛП вызывает `f(const T& value, std::size_t depth, TreeBranch branch)`. Глубина корня — 0, его ветвь — `TreeBranch::root`; остальные ветви — `left` или `right` относительно родителя, независимо от компаратора. Пустое дерево не вызывает callback. Узлы и изменяемые значения не раскрываются; форматирование остаётся задачей вызывающего кода. Сложность `O(n)`, дополнительная память `O(h)`. Исключения callback передаются вызывающему коду; изменять дерево через внешний доступ во время обхода нельзя.

Только множество: `set_union`, `intersection`, `difference`, `is_subset_of`, `contains_subset`; операторы `|`, `&`, `-`, `|=`, `&=`, `-=`, `==`, `!=`, `<=`, `>=`. Равенство определяется ключами, независимо от формы внутренних деревьев. Для бинарных операций компараторы обоих контейнеров должны задавать одинаковую эквивалентность ключей. Результат сохраняет компаратор левого операнда. Составные операторы безопасны при совпадении операндов.

### Требования к типам и исключения

`Compare` должен задавать строгий слабый порядок и быть вызываемым на `const T&` из константного метода. Копирующее и перемещающее создание и перемещающее присваивание компаратора могут бросать. При перемещении дерева компаратор сначала копируется, чтобы источник после передачи узлов сохранял свой порядок и был пригоден для новых вставок.

`swap()` сначала обменивает компараторы, затем корни и размеры. Если обмен компараторов бросит исключение, оно передаётся вызывающему коду. Корни и размеры остаются на месте, но частичное изменение компаратора может нарушить соответствие между ним и порядком узлов.

Узел принимает `T` по значению и перемещает его в поле `value`. Поэтому `T` должен поддерживать перемещающее создание. Для вставки lvalue, копирования дерева, поддерева и фильтрации требуется также копирование; для точного сравнения поддеревьев — `==`. Присваивание `T` при удалении не используется. Деструктор `T` не должен бросать. Значения `NaN` не допускаются с обычным числовым сравнением. Числовой кодек отклоняет не конечные вещественные значения.

При ошибке сравнения или создания нового узла вставка и удаление сохраняют дерево. Копирующее присваивание сначала строит независимую копию. Если этот этап завершился с ошибкой, получатель сохраняется. Затем старое дерево очищается и присваивается компаратор. Если присваивание компаратора бросает, получатель остаётся пустым, источник сохраняет свои узлы. Такой же порядок применяется при перемещающем присваивании. После ошибки сам компаратор сохраняет те гарантии, которые предоставляет его тип; возможность повторного использования зависит от его состояния.

`map`, `where`, фабрики и копирование освобождают частично созданные узлы. Восстановление из строки выполняется во временном контейнере: ошибки формата сохраняют получатель, а ошибка присваивания компаратора при установке результата может оставить его пустым. Эти правила распространяются и на множество, включая составные операции. `clear` и деструкторы дерева и множества имеют спецификацию `noexcept`. Перемещение может бросать. Исключения передаются вызывающему коду. Внешние побочные эффекты пользовательских функций библиотека отменить не может.

## Сериализация

Форматы чувствительны к регистру, токены разделяются пробельными символами. Значения заключаются в двойные кавычки, а `std::quoted` экранирует `"` и `\`. `#` вне кавычек означает пустого потомка. Строковое значение `"#"` является обычным ключом.

```text
TREE1 "8" "3" # # "10" # #
SET1 TREE1 "8" "3" # # "10" # #
```

Префикс `SET1` стоит перед записью внутреннего дерева множества. Пустые контейнеры записываются как `TREE1 #` и `SET1 TREE1 #`. Формат фиксирует обход КЛП с пустыми потомками, чтобы восстановить форму и значения. При чтении проверяются границы каждого узла, поэтому выявляются нарушения относительно дальних предков и дубликаты. Для дерева с пользовательским компаратором при чтении используйте компаратор с тем же порядком, что и при записи.

`from_string` отклоняет незавершённые данные, неверные значения/идентификаторы и лишние токены исключением `std::invalid_argument`. `operator>>` читает ровно один контейнер, допускает последующее чтение из того же потока, при ошибке формата устанавливает `failbit` и сохраняет прежний контейнер. Чтобы поток бросал исключения, задайте `stream.exceptions(std::ios::failbit | std::ios::badbit)`. Лишние токены после контейнера проверяет именно `from_string`, а не `operator>>`.

`value_codec.hpp` отделяет текстовое представление от структуры. Стандартный `ValueCodec<T>` использует потоки с классической локалью и точностью для обратимого представления чисел. Вещественные числа читаются через `std::from_chars`, включая представимые субнормальные значения. Внутри вещественного токена пробелы и начальный `+` не допускаются. Строковая специализация сохраняет весь текст. Для собственного типа можно специализировать `ValueCodec<T>::encode(const T&) -> std::string` и `decode(const std::string&) -> T`. Для неверного значения декодер бросает `std::invalid_argument`. Кодек `Student` сохраняет ID, имя и дату рождения, а порядок записей по ID задаётся отдельно. Специализация для комплексных чисел использует представление `(real,imag)`. Порядок задаёт пользовательский компаратор.

## Демонстрация и тесты

Главное меню содержит BST, множества и демонстрацию других типов. В разделах BST и множества сохранены номера операций: данные — `1`, `2`, `3`, `12`; вставка/удаление/поиск — `4`–`6`; `map`/`where`/`reduce` — `7`–`9`; сериализация — `10`, `11`. Для дерева `13` показывает шесть обходов в глубину и BFS, `14` извлекает поддерево, `15` проверяет вхождение. Для множества `13` демонстрирует объединение, пересечение, обе разности, включение и равенство. `99` повторно показывает сгруппированное меню, `0` возвращает назад. После действия выводится короткое приглашение, без повторения всего меню.

Обычный просмотр показывает размер и значения в ЛКП. Для BST до 20 узлов включительно дополнительно выводится иерархия с ветвями `L` и `R`. Пустой контейнер имеет отдельное сообщение. Ручной ввод принимает до 20 000 чисел через пробел. При генерации задаются число попыток вставки до 20 000, диапазон, seed и порядок вставки. После генерации видны число попыток, уникальных значений и повторов. Просмотр и вывод каждого обхода показывают до 100 значений. `map` демонстрирует преобразование `a*x+b`, `where` — отбор по интервалу, `reduce` — сумму. Для `map`, `where` и извлечения поддерева выводятся источник и независимый результат.

В подменю других типов каждый пример открывается отдельно: числа `double`, строки в `OrderedSet`, поля студента (ID, имя, дата рождения), комплексные числа в математической записи. Порядок сравнения поясняется рядом с примером. Сериализация показывается только по явному выбору: `10` в разделе контейнера или `1` внутри примера типа. Строка выводится целиком на отдельной строке, без изменения формата. Все действия и визуализация используют публичный API; библиотека не зависит от CLI.

`tests/tree_test.cpp` и `tests/set_test.cpp` проверяют обходы и итераторы, операции над множествами, пользовательские компараторы, копирование и перемещение. Есть проверки ошибочных строк и сравнение со `std::set` на воспроизводимых случайных операциях. Деревья из 100 000 узлов в форме цепочки строятся из сериализованной строки для проверки глубокого обхода, копирования и очистки. `tests/containers_test.cpp` проверяет рост буферов, кольцевую очередь, освобождение ресурсов и исключения при копировании и перемещении.

## Как устроены хранение и владение

Корень и обе дочерние связи хранятся в `std::shared_ptr<Node>`, узлы создаются через `std::make_shared`. При обходах в глубину задания хранятся в стеке, а BFS помещает узлы в очередь. Поиск использует локальный указатель на текущий узел. Для вставки и удаления дополнительно запоминается родитель. При чтении дерева стек хранит родителя, направление связи и допустимые границы ключа. Узлы остаются внутри библиотеки.

В массиве, очереди и дереве копирующее и перемещающее присваивания реализованы отдельными операторами с проверкой самоприсваивания. При копировании сначала создаётся независимая копия, затем её ресурсы передаются полям получателя. Перемещение передаёт существующий буфер или корень и обнуляет размер источника; у массива и очереди также обнуляется ёмкость. Старое дерево перед заменой корня очищается итеративно. Компаратор присваивается после очистки получателя, затем передаётся корень.

Копирование создаёт новую структуру с новыми узлами; `map`, `where` и `subtree` также независимы. При исключении временный результат очищается тем же итеративным алгоритмом, что и готовое дерево. Удаление переставляет связи, сохраняя адреса уцелевших значений. При очистке каждый удаляемый корень освобождается после отсоединения потомков: нет каскада деструкторов даже у длинной цепочки.

| Контейнер | Хранение и назначение | Стоимость |
|---|---|---|
| `DynamicArray<T>` | Непрерывный буфер `std::unique_ptr<T[]>` создаётся через `std::make_unique<T[]>(capacity)`. Все ячейки содержат объекты `T`, созданные по умолчанию. Копирование сохраняет размер и ёмкость в отдельном буфере. Конструктор `DynamicArray<int>(8)` создаёт пустой массив ёмкостью 8, а `DynamicArray<int>{8}` — массив с одним элементом 8. Используется в стеке, генерации данных, визуализации и бенчмарке. | Доступ по индексу и удаление с конца — O(1), добавление — амортизированно O(1) благодаря удвоению ёмкости. |
| `Stack<T>` | LIFO поверх `DynamicArray<T>`. Рабочий стек обходов, копирования, сериализации и её разбора. | `top`, `pop` — O(1); `push` — амортизированно O(1). |
| `Queue<T>` | Кольцевой буфер `std::unique_ptr<T[]>` создаётся через `std::make_unique<T[]>(capacity)`. Первая вставка выделяет четыре ячейки; при заполнении ёмкость удваивается. При расширении значения переносятся в порядке FIFO, индекс начала сбрасывается в ноль. Копирование сохраняет ёмкость и нормализует начало кольца в ноль. Используется для обхода по уровням. | `front`, `pop` — O(1); `push` — амортизированно O(1). |

`DynamicArray<T>`, `Stack<T>` и `Queue<T>` требуют создания `T{}` и присваивания. У `Student` есть пустое состояние по умолчанию (ID 0 и пустые строки) для хранения в таких контейнерах. Конструктор заполненной записи и чтение из строки проверяют положительный ID и непустые поля.

При удалении и очистке массив и очередь присваивают удаляемым ячейкам `T{}`. Для умных указателей это сразу освобождает владение объектом. Для других типов освобождение ресурсов определяется их присваиванием. Сами объекты ячеек живут до освобождения буфера. Очистка сохраняет ёмкость. Индексация массива и извлечение из пустого контейнера проверяются (`std::out_of_range`). Если сброс значения может бросать, `clear()` массива, стека и очереди также может бросать. Размер и индекс начала изменяются только после успешного сброса ячейки.

В `DynamicArray::reserve`, `push_back`, а также при расширении и вставке в `Queue` используется прямое перемещающее присваивание через `std::move`. При исключении из перемещающего присваивания часть исходных значений может остаться перемещённой, даже если тип поддерживает копирование. При отказе выделения памяти или создании ячеек исходный контейнер сохраняется. Если расширение уже завершилось, а присваивание добавляемого значения выбросило исключение, размер остаётся прежним, ёмкость увеличена, прежние ссылки недействительны. При бросающем присваивании в существующую ячейку или сбросе `T{}` состояние самой ячейки определяется гарантиями типа `T`.

## Сложность и память

Пусть `n` — размер, `h` — высота дерева. Вставка, поиск и удаление требуют до `O(h)` времени. Для дерева, построенного вставкой уникальных ключей в случайном порядке, ожидаемая высота — `O(log n)`. Для цепочки она равна `O(n)`. Последовательная вставка отсортированных значений требует `O(n²)`.

Обходы в глубину, сериализация, структурное копирование и восстановление из КЛП требуют `O(n)` операций над узлами и стека `O(h)`; стоимость кодирования значений учитывается отдельно. BFS проходит дерево за `O(n)` и использует `O(w)` дополнительной памяти, где `w` — максимальное число узлов на одном уровне. Очистка использует повороты и занимает `O(n)` времени, `O(1)` дополнительной памяти, без рекурсии и выделений. Все пути обработки собственных узлов итеративны, включая аварийное освобождение частично построенного дерева.

Извлечение поддерева из `k` узлов и проверка вхождения требуют до `O(h+k)` времени. `map` и `where` выполняют повторные вставки и в худшем случае занимают `O(n²)`. Стоимость объединения, пересечения и разности зависит от высот исходных и результирующих деревьев. При вырождении возможна квадратичная сложность.

## Бенчмарки

```sh
./build/tree_lab_benchmark --max-n 1000000 --repeats 3 --seed 42 \
  --sorted-max 20000 --memory-mib 512 --max-seconds 5 \
  --output results/benchmark.csv
python3 -m venv .venv
.venv/bin/python -m pip install matplotlib
.venv/bin/python benchmarks/plot.py results/benchmark.csv --output results/benchmark.png
```

Python и Matplotlib используются только для графиков. Бенчмарк написан на C++. Размеры: `10⁴`, `2·10⁴`, затем степени десяти до `--max-n` и сам `--max-n`. Допускается запрос до `10⁸`. Для каждой комбинации размера и порядка есть несколько повторов с сохранённым seed. Измеряются полные пакеты вставок, успешных поисков и удалений; подготовка данных, перемешивание и финальная очистка вне таймера. Поиск и удаление получают перемешанную последовательность в обоих сценариях.

Защита от чрезмерных расходов: `--sorted-max` ограничивает отсортированный сценарий, `--memory-mib` оценивает бюджет по 96 байтам на ключ, `--max-seconds` ограничивает каждый пакет с проверкой каждые 1024 операции. Это мягкое ограничение времени и оценка памяти, а не ограничение RSS процесса. CSV содержит полные параметры, версию компилятора, режим сборки, число реально выполненных операций и статус. `timeout`, `allocation_failed` и `skipped_*` не являются полными измерениями. График использует только полные строки `ok`, показывает медиану и диапазон min–max; экстраполяция отсутствует.

CSV и графики создаются при запуске и исключены из контроля версий. Чтобы увидеть фактически измеренные размеры, смотрите столбцы `n`, `operations` и `status` в CSV. Параметр `--max-n` задаёт верхнюю границу запрошенных размеров.
